# 性能说明

本文档说明 omr 的性能构成、量级与调优线索。所有数字出自测试语料（41 张扫描，
1.0 到 3.7 兆像素），在 12 核开发机上用 `cargo run --release --example bench 10`
测得，为多次取最优的稳态值；绝对值随机器而变，相对关系是稳定的。

## 总量

| 阶段 | 平均耗时 | 说明 |
| --- | --- | --- |
| JPEG 解码 | 约 5.5 ms/张 | 与识别本身无关，是入口成本 |
| 模板解析 | 约 0.5 ms/份 | GBK 解码 + XML + base64 图章 |
| 识别（配准 + 测量 + 判定） | 约 5.8 ms/张 | 见下文分解 |
| 端到端吞吐 | 约 460 MP/s | 含 JPEG 解码 |

扫描仪的出图速率远低于此，识别不是流水线瓶颈。

## 识别耗时的构成

配准路径决定耗时上限，因为测量与判定本身都很便宜（约 1 到 2 ms）：

| 扫描 | 识别合计 | 路径 |
| --- | --- | --- |
| `2/data/1`（角标齐全，30 题） | 3.9 ms | `corner_registered` |
| `4/data/1`（角标齐全 + 条形码） | 4.2 ms | `corner_registered` |
| `5/data/1`（三角形角标） | 约 8 ms | `corner_registered` |
| `6/data/1`（角标被裁掉，0.98 MP） | 约 9 ms | `content_aligned` |
| `3/data/4`（部分角标，3.3 MP） | 约 23 ms | `content_aligned` |

规律很直接：

* **角标路径接近常数时间。** 定位四个斑，拟合一次投影变换，几毫秒完成，与
  页面像素量基本无关（斑点搜索只覆盖角落邻域）。图章相关共享图章统计量、
  网格按行并行，三角形大图章的角标也只要约 5 ms。
* **内容对齐按需付费，且已并行化。** 它在整幅扫描上做二值化 + 9×5 盒式模糊
  （滑动窗口和，u16 整数，无除法）并建 u32 积分图像，全部 O(像素) 阶段用
  rayon 按行带并行；粗网格（±600 px、步长 8）按 dy 行并行打分，每个点每个
  矩形只做四次查表。剩余成本与像素量成比例：0.98 MP 的 case 6 约 9 ms，
  3.3 MP 的 case 3 约 23 ms。
* **部分角标最贵。** case 3/data/5 有角标但残差超限，配准先完整走一遍角标
  路径（含图章相关性验证），失败后再完整走一遍内容对齐，两条路径的成本
  相加。

## 关键实现选择

* **整数滑动窗口模糊。** 盒式模糊按可分离两级做，每像素约两次加减：竖直级
  把 9 行阈值化结果滑进 u16，水平级把 5 个 u16 滑进另一个 u16，全程无除法。
  积分图像是 u32。
* **打分的预计算布局。** 块与单元格的整数坐标、面积在搜索前算好；打分闭包
  内没有乘法，只有边界检查加每个矩形四次 u32 载入。
* **整数图章相关。** 归一化相关的累加器从 f64 换成 u32/u64，图章自身的
  `sum_p`、`sum_pp` 在整个网格上只算一次（`StampStats`），粗细两级网格都走
  无钳位的连续内存路径；比浮点版本快约 3 倍。
* **共享的惰性 darkness 积分图。** 角标路径逐轮扩大搜索半径时，darkness
  网格的总扫描量累计到约一幅扫描的像素量后才构建一次积分图，此前的小网格
  直接求和更便宜。构建后每个窗口四次查表，整个配准最多构建一次。
* **升级循环去重。** 图章搜索窗口钳在 40 px，半径升级超过该值后重复图章搜
  索只会得到相同结果，故后续轮次只搜 darkness，不再跑相关。
* **条形码仿射快路径。** 仿射变换下双线性的 x 抽头是每行共享的一张表
  （SoA 三数组），墨水采样按行 rayon 并行，单次解码从 3.3 ms 降到 0.6 ms；
  投影拟合回退到逐点采样。
* **PNG 编码用 Fast。** 压缩级别只影响体积与编码时间，不改变像素：High 在
  2 MP 样张上花约 170 ms 只省约 45% 体积，Fast 只要约 8 ms，标注输出不再
  主导流水线。
* **逐块并行测量。** 所有题目块合并成一次 rayon 并行扫描；此前只有块内单
  元格并行，四格小块的并行开销盖过了工作量。

## 内容对齐内部的成本结构

1. **模糊与积分**：全部 O(像素) 阶段，已按行带并行。
2. **粗网格**：22801 个点，按 dy 行并行（rayon reduce，平分时取更小 dy/dx
   保证确定性），每点每个矩形四次查表。
3. **细网格**：17×17 = 289 个点，单线程。

调优线索：

* 想压低内容对齐的耗时，最有杠杆的是搜索范围 `span = 600`：模板页小于扫描件
  时（配准只需小幅平移），收窄到页面尺寸差即可线性提速。
* `--crop` 提供的裁剪直接减小 O(像素) 阶段的面积，双页合扫务必使用。
* 线程数可用 `omr-batch --jobs` 或 `RAYON_NUM_THREADS` 控制；内容对齐在 4 到
  8 线程间收益最大。

## 标注输出

标注图按扫描件原分辨率写出，PNG 无损编码（`Compression::Fast`），不缩放、
不压缩像素值。编码耗时约 8 ms/张；体积约为 High 级别的 1.8 倍，属可接受的
取舍。

## 测量方法

`examples/bench.rs` 是唯一的性能基准，没有单独的 criterion 套件：

* 每张扫描预热两次，然后取 N 轮（默认 10）中的最优值，描述稳态而非冷启动；
* JPEG 解码单独计时，不与识别混在一起；
* 被拒绝的错误页（`registration_failed`）是定义内的结果，不计为失败；
* 快照测试不计时，只校验正确性。优化前后唯一的验收标准是 41 张快照逐字段
  相等。

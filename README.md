# omr

读取本仓库阅卷扫描仪所用 `.mb` 答题卡模板的识别库。它解析模板，将扫描件配准到
模板上，并报告考生填涂的结果。

## 模板格式

`1.mb` 是声明为 `gb2312` 的 XML，解析前按 GBK 解码。文档中每个 `<page>` 描述
答题卡的一个扫描面。

| 元素 | 属性 | 含义 |
| --- | --- | --- |
| `mb` | `mbid`、`dpi`、`layout` | 模板根节点与标识 |
| `page` | `dpi`、`deskew`、`binaryThrould` | 一个扫描面 |
| `mli` | `x`、`y`、`x1..y2`、`width`、`height`、`img` | 配准标记：搜索窗口、命中框与 base64 灰度图章 |
| `omr` | `ogname`、`omrType`、`x`、`y`、`width`、`height` | 一个答题块 |
| `omr` | `ax`、`ay`、`onum`、`inum`、`omrmap`、`rc` | 块内的单元格 |
| `omr` | `stno`、`answer`、`score` | 题号、参考答案、分值 |

样例中出现的块类型：

| `omrType` | `fillType` | 名称 | 含义 |
| --- | --- | --- | --- |
| `1` | `1` | `PNO` | 页码，每个扫描面一个 |
| `2` | `1` | `KSH.n` | 考号数字网格：每位数字一列十个单元格 |
| `2` | `7` | `KSH` | 承载考号的 Code 128 条形码 |
| `5` | `1` | `S#n` | 计分的单选题 |
| `7` | `1` | `QK` | 缺考标记框 |

`omrType` 2 同时覆盖考号的两种形态，只靠 `fillType` 区分。

单元格几何为 `x + ax[2c] .. x + ax[2c+1]` 与 `y + ay[2r] .. y + ay[2r+1]`。
`rc` 重复声明了同一组矩形，是冗余信息。

`density` 与 `densityS` 是制作模板时记录的测量值，与被读扫描件的答案无关。

## 识别流程

1. **配准。** 角标按实心暗斑定位，用投影变换拟合到模板角点。搜索从模板原位
   和几个缩放猜测出发，因此可以容忍缩放、旋转和轻微透视。四个角标中有一个
   被折角盖住、或某一个检测落到字迹上时，剩下三个仍能给出旋转、缩放和偏移；
   拟合会反复丢掉与其余角标不一致的检测。
2. **分组。** 题目块按所属模板列分组。组内每一行都印有选项括号，铅笔填涂则
   只出现在个别行，因此每列先按自身中位数归一化再测量。
3. **测量。** 单元格在公共网格上重采样，对列基线做阈值，再腐蚀掉细的印刷
   笔画，避免它们参与计分。
4. **判定。** 得分最强的单元格胜出；并列、多选和淡涂会带原因置为
   `needs_review`，每个读数都带 `confidence`。
5. **条形码。** 先从周围文字中分离条码行，在多个阈值下读取元素宽度，只有
   模 103 校验位通过才接受结果。

页码框、缺考框和数字单元格是孤立的印刷形状，没有同类可比较，因此逐格独立
测量：空选项在印刷括号内保留明亮内部，已填涂的则是实心覆盖。

角标记录的位置可能只是生成器的搜索窗口原点，而答题块直接使用页面坐标。拟合
出的整个变换（含平移）因此作用在答题块上：纸张在扫描台上的偏移、旋转和缩放
都是真实的，只取线性部分会让旋转绕模板原点而不是绕纸张中心发生，页面另一侧
的块会整体偏出印刷框。

配准结果还要经得起印刷内容的检验：拟合出的变换必须让声明单元格压在印刷括号
上，否则视为落到了页面自身的墨点上，改走内容对齐。

## 用法

```rust
use omr::{register_scan, Gray, Options, Template};

let template = Template::parse_file("1.mb")?;
let scan = Gray::open("scan.jpg")?;
let result = register_scan(&template, 0, &scan, None, Options::default())?;

for selection in &result.selections {
    println!("{:?} {:?}", selection.question, selection.selected);
}
```

`register_scan` 接受可选裁剪参数，双页合扫的展开件需要它。

## 命令行

`omr` 读取扫描件并输出一张标注图。

```text
cargo run --release --bin omr -- tests/01/1.mb tests/01/data/1/1.jpg
cargo run --release --bin omr -- tests/01/1.mb tests/01/data/1/2.jpg -p 1 -o out.png
```

```text
usage: omr <template.mb> <scan.jpg> [options]

options:
  -p, --page <n>        模板页序号，从 0 计（默认 0）
  -o, --out <path>      输出图像，默认 <scan>.annotated.png
      --crop <rect>     扫描件像素坐标 x0,y0,x1,y1，用于双页合扫
      --scale <n>       标签与线条缩放（默认 2）
      --no-cells        不勾画每个选项单元格
      --no-registration 不绘制拟合出的页角
      --json            在 stdout 打印 JSON 读数
```

标注图显示拟合的页角、每个选项单元格、绿色或琥珀色标出的选中项、红色的竞争
涂点，以及考号、页码和缺考状态。读数同时打印到 stderr。

## 批量识别

`omr-batch` 递归找出目录下所有图片，用同一份模板并行识别：

```text
cargo run --release --bin omr-batch -- tests/cases/6/5.mb scans/ -o out/
```

```text
usage: omr-batch <template.mb> <directory> [options]

options:
  -p, --page <n>        模板页序号，从 0 计（默认 0）
  -o, --out <dir>       标注图输出目录，按输入目录结构镜像存放；不传则不写图
  -j, --jobs <n>        工作线程数（默认全部核心）
      --scale <n>       标签与线条缩放（默认 2）
      --no-cells        不勾画每个选项单元格
      --no-registration 不绘制拟合出的页角
      --json            在 stdout 打印每张扫描的 JSON（NDJSON，每行一条）
      --fail-fast       出现失败后不再调度新的扫描
```

逐张结果按路径排序打印到 stdout，汇总打印到 stderr，退出码在全部成功时为
0、存在失败时为 1。`--json` 打开的 stdout 每行形如
`{"scan": "…", "result": {…}}` 或 `{"scan": "…", "error": "…"}`，`result`
与 `omr --json` 的输出结构相同。

## 缺失角标

角标是主要的对齐依据，但不是全部。四个角标里被折角、翻边或裁切盖住一个时，
剩余三个足以定出纸张的旋转、缩放和偏移，读数照常给出；两个及以上确实无法
定位时，`register` 回退到 **内容对齐**：每个含单元格的块（题目行、页码）贡献
一个分数——在二值化并做盒式模糊的扫描副本上，取声明单元格内的平均墨水减去
单元格之间间隙的平均墨水。
空白纸得 0 分，真实偏移处每个单元格压住墨水、每个间隙压住纸面。平移量由粗到
细的网格搜索求出；所有块联合打分，消除单题行固有的行距混叠；每块区域向右
延展一个单元格间距，惩罚恰好左移一格的 x 向混叠；靠近页面边缘的块只有在
大部分布局仍然可见时才被跳过。最终分数必须超过拟合阈值，因此另一张模板的
扫描件会被拒绝而不是误读。

JSON 中的 `registration.mode` 报告本次读数来自哪条路径：

| 模式 | 含义 |
| --- | --- |
| `corner_registered` | 至少三个角标找到并完成拟合（四个角标齐全时也用四个） |
| `content_aligned` | 角标不足以拟合；按印刷内容对齐，仅平移 |

内容对齐页面的置信度乘以 0.7：偏移是可靠的，但未补偿任何旋转或缩放。

`registration.max_residual` 是**应用后的变换**在角标上的残差。四个角标的投影拟合
是过定的（4 点定 8 参），按构造穿过每一个点，因此它的残差恒为 0、没有诊断价值；
这里改为报告该变换本身的重投影误差，四个角标各自偏离多少一目了然。

## 性能

详细的数据、耗时构成与调优线索见 [docs/performance.md](docs/performance.md)。

```text
cargo run --release --example bench [rounds]
```

报告每张扫描的平均识别耗时、伴随的 JPEG 解码耗时，以及语料中最慢与最快的
样张。在测试语料（33 张扫描，1.8 到 4.4 兆像素）上，识别平均约 4 毫秒每张，
JPEG 解码再加约 5 毫秒；两者都远低于扫描仪的出图速率。

## 测试

```text
cargo test --release
```

`tests/cases/<n>/` 存放一套模板与一个装扫描件的 `data/` 目录。每张扫描的读数
存放在 `tests/cases/<n>/expected/`：

| 文件 | 内容 |
| --- | --- |
| `expected/<sheet>/<page>.json` | 答案、考号、条形码、页码、缺考状态、配准质量与标注摘要 |
| `expected/<sheet>/<page>.png` | 同一读数绘制在扫描件上，全尺寸无损 |

测试重新计算每个读数并逐字段比对，配准、单元格测量或判定的任何变化都会以
diff 的形式暴露。置信度保留两位小数，无伤大雅的舍入漂移不会导致失败，而分离
度的真实变化会。角标找不到的扫描件记录 `registration_failed` 原因而不是读数。

标注图按扫描件自身分辨率写出并无损编码，因此存储的图像可以与原扫描逐像素
比对。文件格式对调色板友好，但并未做调色板压缩：每个扫描像素保持原值。

有意修改后重新生成全部快照：

```text
cargo run --release --bin snapshot
```

它会同时写出 JSON 与图像。用 `--no-draw` 只重写 JSON，传入目录可处理另一套
语料。

## 已知限制

* 模板中的 `answer` 是参考答案，不是考生的作答。识别器只报告涂点，从不报告
  答案本身。
* 没有 `omr` 块的模板页会读出空结果，这对主观题面是正确的，但也掩盖了误读，
  例如把答题卡的另一面交给它读。
* 条形码只在印刷符号清晰时解码；读不到条形码应视为"改抄印刷数字"，而不是
  扫描件出错。
* `tests/cases/2` 下两张扫描是另一张答题卡的错误页。配准将其拒绝（1.1 倍
  缩放下约 130 px 的角标误差），读数记录为 `registration_failed`，这正是预期
  行为：拒绝胜过从错位的网格上作答。
* 页序号取自扫描文件名，默认 0。用页 0 读主观题面时，除印刷框外找不到任何
  涂点，因此多页模板务必传 `-p`。
